# WordPress.org 目录提审记录

拟申请标识为 `linglingqi-builder-open`，提交版本为 `1.3.2`。候选包以 GitHub 正式版 `v1.3.1` 为基线，版本号用于区分两个发行包。保留目录、入口文件与页面数据结构，目录版使用 WordPress.org 更新服务。现有 GitHub 正式版继续使用当前渠道。

## 构建与校验

在仓库根目录使用 Python、PHP 7.4 或更高版本及 esbuild 0.25.12 运行下列命令。输出文件须尚未存在，构建会先校验输入包的 SHA-256。PHP 或 esbuild 未加入 PATH 时，可用 `--php` 或 `--esbuild` 指定路径。

构建输入为项目正式发布的 1.3.1 ZIP。这个分支包含构建脚本、PHP 翻译域迁移工具及目录版 readme。Python 构建脚本逐项列出源码补丁，目录包内包含相应的可读 PHP 和 JavaScript。[构建输入 ZIP](https://github.com/2405474279/linglingqi-builder-open/releases/download/v1.3.1/linglingqi-builder-open-v1.3.1.zip) · [构建脚本](../../tools/build-wordpress-org.py)

```powershell
python tools/build-wordpress-org.py linglingqi-builder-open-v1.3.1.zip linglingqi-builder-open-v1.3.2-wordpress-org.zip
```

候选包共 2,334 个文件，CRC 通过，大小 14,203,761 字节，SHA-256 为 `67588bec62841e1ffecd6a1d55647fd3ac02def70c02b98db0e883b8ebfab417`。

## 提交与验收

- WordPress 6.8／PHP 7.4.33 和 WordPress 7.1.5／PHP 8.4.27 的隔离 WordPress 站均已实测覆盖安装、保持启用、保留已有原生页面数据，并确认自定义 GitHub 更新钩子未注册。两套站点使用 MySQL 8.4.6。
- PHP 的翻译域与 MO/PO 文件已迁移到 `linglingqi-builder-open`。现有 JavaScript 的独立语言包仍随包提供。复扫已确认纯 PHP 调用的翻译域不匹配问题清零。
- 四套脚本改用 WordPress 的 `react-jsx-runtime` 依赖，压缩包与资源清单同步更新。复扫已确认内嵌 JSX 运行时问题清零。两套站点已实测加载压缩资源、从面板插入原子选项卡、保存，以及匿名访客切换选项卡。
- 改用 WordPress 核心文件操作 API 并补齐输出转义。已在上述两站验证 WXR 导出为合法 XML，兼容普通及 zlib 流读取，并验证临时文件删除和非递归目录清理。
- 经典页面首次切换为构建器页面需通过当前账号和页面绑定的随机令牌确认。两站均验证未签名请求不会写入页面数据，后台签发的链接可正常切换。已使用构建器的页面可继续从原有链接打开。预览调试错误仅在启用站点调试且当前账号具有管理权限时输出，并进行 HTML 转义。
- 上一轮目录扫描已达到 0 条错误。剩余警告主要与兼容前缀、既有数据库维护操作和未来 React 19 兼容有关。两个已测 WordPress 版本均使用 React 18.3.1。目录审核进度以 WordPress.org 回执为准。
- 获批后的验收使用干净站点，从后台「插件 → 安装插件」搜索并安装目录里的实际发布包。另用现有 GitHub 版副本验证跨渠道覆盖和页面回读。
