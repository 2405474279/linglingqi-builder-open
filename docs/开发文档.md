# 凌凌漆开源版开发文档

本项目基于 Elementor 4.3.6。开发范围为开源版 `linglingqi-builder-open/`。1.1.0 提供经典可视化编辑器、容器布局，以及「基础」和「常规」两组组件。站点级样式继续使用 Elementor 数据结构。

## 开发环境

在独立 WordPress 实例启用源码目录或本地安装包。首版实测使用 WordPress 7.1.4、PHP 8.3.30 和 Twenty Twenty-Five。需要确认兼容下限时，在目标 WordPress 和 PHP 组合上单独运行回归。

本版仍使用 `Elementor\*` 命名空间、`elementor` 文本域和 `_elementor_*` 数据键。同一实例只启用一个 Elementor 或凌凌漆版本。为开源版修改源码时，以 `linglingqi-builder-open/` 为工作目录。

## 文档数据和组件标识

- `_elementor_data` 保存元素树。元素含 `id`、`elType`、`settings` 和 `elements`，组件节点另有 `widgetType`。容器的子元素位于它的 `elements` 内。已发布页面会按已有的 `widgetType` 查找组件，因此修改组件名或控件键前应评估已有页面。
- `_elementor_edit_mode` 标记构造器编辑模式，`_elementor_page_settings` 保存文档设置，`_elementor_template_type` 是内部文档类型。修改页面数据应通过编辑器完成。
- `elementor_active_kit` 指向承载全局样式的内部文档。开源版仍注册私有的 `elementor_library` 存储类型供站点样式使用。维护时保留该数据及其引用。 [文档常量](../linglingqi-builder-open/core/base/document.php) · [私有样式存储](../linglingqi-builder-open/includes/template-library/sources/local.php)
- 保存动作在 `elementor_ajax` 的鉴权和文档权限检查下运行。内部 AJAX 和 REST 适合诊断及本版测试，集成代码应使用相应的扩展钩子。 [AJAX 分派](../linglingqi-builder-open/core/common/modules/ajax/module.php)

## 用独立扩展插件注册组件

团队自己的组件可放在单独的 WordPress 插件，通过 `elementor/widgets/register` 注册。下例放在独立扩展的主 PHP 文件中，启用后可在组件面板找到「简单提示」。

```php
<?php
/**
 * Plugin Name: 凌凌漆示例组件
 */

if ( ! defined( 'ABSPATH' ) ) {
	exit;
}

add_action( 'elementor/widgets/register', static function ( \Elementor\Widgets_Manager $widgets_manager ) {
	$widgets_manager->register( new class extends \Elementor\Widget_Base {
		public function get_name() {
			return 'example-simple-notice';
		}

		public function get_title() {
			return '简单提示';
		}

		public function get_categories() {
			return [ 'basic' ];
		}

		protected function register_controls() {
			$this->start_controls_section( 'notice_content', [
				'label' => '内容',
			] );
			$this->add_control( 'message', [
				'label' => '提示文字',
				'type' => \Elementor\Controls_Manager::TEXT,
				'default' => '请填写提示文字',
			] );
			$this->end_controls_section();
		}

		protected function render() {
			$message = $this->get_settings_for_display( 'message' );
			echo '<p class="example-simple-notice">' . esc_html( $message ) . '</p>';
		}
	} );
} );
```

控制项声明放在 `register_controls()`，前台 HTML 在 `render()` 按输出上下文转义。使用客户端实时模板时，可参考标题组件的 `content_template()`。组件添加独立 CSS 或 JS 时，先注册对应 WordPress 资源，再通过组件依赖方法声明加载。 [标题组件实现](../linglingqi-builder-open/includes/widgets/heading.php)

## 修改编辑器资源

编辑器主脚本在 `assets/js/editor.js`，顶栏和文档动作位于 `assets/js/packages/` 的相应包。资源修改应同步更新同名 `.min.js`。调整资源依赖时同时检查对应的 `.asset.php`。隔离环境可用 WordPress 的 `SCRIPT_DEBUG` 分别核对开发和压缩资源。

现有源码目录交付的是可安装的 PHP、编辑器资源及匹配的压缩文件。修改单个现有 JS 包时，复用已安装的 esbuild 更新压缩文件。以主脚本为例，从源码目录执行下面命令。

```sh
node --check assets/js/editor.js
esbuild assets/js/editor.js --minify --legal-comments=inline --outfile=assets/js/editor.min.js
node --check assets/js/editor.min.js
```

## 回归检查

1. 对改动过的 PHP 运行 `php -l 路径`，对实际加载的 JS 运行 `node --check 路径`。
2. 启用插件。从页面列表打开新建页和已有页。添加容器和基础组件，再验证标题编辑、设备预览和样式面板。
3. 保存草稿并刷新编辑器。发布测试页并匿名打开，核对内容、层级、样式和关键点击。核对新增的 PHP 及浏览器错误。
4. 检查后台、画布与保存菜单中的功能入口符合开源版范围。验证「基础」「常规」面板和嵌套组件，确认已有经典组件页面仍能渲染。
5. 发包前在隔离站从最终 ZIP 安装，核对插件版本和关键路径。 [版本与兼容说明](版本与兼容说明.md)
