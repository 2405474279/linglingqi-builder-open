# 凌凌漆开源版安装与使用

适用于 1.3.0 及 1.3.1。可以用它制作和编辑 WordPress 页面或文章，在容器中排列内容，并按桌面、平板和手机分别调整版式。

## 安装和打开编辑器

1. 确认环境满足 WordPress 6.8 和 PHP 7.4 下限。两套实测组合见 [发布验收](1.3.0发布验收.md)。
2. 从 WordPress 后台进入「插件 → 安装插件 → 上传插件」，选择 ZIP，然后安装并启用。同一个 WordPress 站点仅启用一个 Elementor 或凌凌漆版本。现有站点先在副本上验证。 [1.3.1 安装包](https://github.com/2405474279/linglingqi-builder-open/releases/download/v1.3.1/linglingqi-builder-open-v1.3.1.zip) · [升级与恢复](升级说明.md)
3. 打开「页面 → 新建页面」，或在页面列表找到已有页面，点击「使用凌凌漆编辑」。也可以从「网站可视化构建器」进入新建或编辑入口。文章编辑入口取决于插件设置中启用的内容类型。
4. 中文界面可在「设置 → 常规 → 站点语言」选择简体中文。浏览器中的界面文字可能随账号语言变化，按对应的控件功能找到入口。

按组件查阅图文操作、新建第一个页面或维护旧页面。[入门教程](https://bpvips.com/3262) · [官网组件教程全集](https://bpvips.com/collection/linglingqi-builder)

## 后台在线更新

1. 从 1.3.0 或更早版本升级时，先备份数据库、媒体和插件，在「插件 → 安装插件 → 上传插件」选择 1.3.1 ZIP，并确认覆盖。启用 1.3.1 后才能检查后续在线更新。
2. 用有权更新插件的账号打开「仪表盘 → 更新」，点击「再次检查」。多站点请使用网络管理后台。发现新版本后可在该页或「已安装的插件」中更新。
3. 站点满足目标安装包的 WordPress 和 PHP 要求，且 WordPress 允许修改插件文件。若后台要求文件系统凭据，使用主机提供的凭据。
4. 服务器要能通过 HTTPS 访问 `api.wordpress.org`、`api.github.com`、`github.com` 以及 GitHub 下载跳转使用的 `release-assets.githubusercontent.com`。公开 Release 无需 GitHub 登录或令牌。查询结果短期缓存，GitHub 暂时限流时可稍后再次检查。
5. 项目需已发布更高版本的 GitHub 正式 Release，并附上对应的 WordPress 安装 ZIP。预发布版本不会进入此更新渠道。无法联网的站点可继续下载 ZIP 后手动覆盖。

## 从空白页面到可预览草稿

1. 在画布点击加号，选一个容器布局。简单页面可以从单列开始。
2. 从左侧组件面板添加标题、文本、图片或按钮。点选画布上的组件，使用面板的「内容」「样式」「高级」修改文字、外观和间距。
3. 给内容图片填写有意义的替代文字。给按钮设置实际目标，预览时点开核对链接。
4. 用顶部设备选项查看桌面、平板、手机布局。重点检查标题换行、图片裁剪和容器间距。
5. 从「保存选项」选择「保存草稿」。使用「预览更改」看实际渲染，确认无误后点击「发布」。已发布页面的直接更新会改变访客看到的内容。

## 组件面板

| 分类 | 组件 |
| --- | --- |
| V4 原子元素 | Flex、Grid、标题、段落、图片、按钮、分隔线、原子 FAQ、原子选项卡 |
| 基础 | 标题、图片、文本编辑器、视频、按钮、分隔线、间距、Google 地图、图标 |
| 常规 | 图片盒、图标盒、图片轮播、基础图库、图标列表、计数器、进度条、推荐语、选项卡、手风琴、社交图标、提示、SoundCloud、短代码、HTML、菜单锚点、侧栏、阅读更多、评级、路径文字 |

容器用于布局。开启容器时，面板默认提供可嵌套内容的选项卡和手风琴。经典选项卡、手风琴、切换和星级评分继续支持已有页面。HTML 的可见性取决于当前账号权限。地图、SoundCloud 和采用外部来源的视频会由所选服务加载。

新装默认优先 V4。管理员可以在「网站可视化构建器 → 编辑器模式」切换新建页偏好。既有经典、原子和混合页仍使用原组件。 [V4 编辑、FAQ、选项卡和区块复用](V4编辑、复用与扩展.md)

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 页面列表没有编辑入口 | 核对插件已启用、设置中对应的内容类型已启用，以及当前账号有权编辑该页面。 |
| 画布一直加载 | 检查预览是否能打开、插件脚本是否正常加载，以及浏览器控制台和 WordPress 日志中的首个新错误。 |
| 保存后前台看起来没变 | 先核对保存结果和页面状态。草稿改动通过预览核对。已发布页面可重新打开前台地址并检查站点缓存。 |
| 迁入的页面缺少组件 | 盘点页面原有组件，逐个替换为当前版本提供的组件，再检查页面和设备版式。 [版本与兼容说明](版本与兼容说明.md) |
