# Agent 使用凌凌漆开源版建站

以 1.0.0 为准。建页和改页通过 WordPress 后台打开可视化编辑器，使用原有的组件面板、预览和保存流程。插件源码扩展另见开发文档。[开发文档](开发文档.md)

## 任务开始前

- 核对目标站点地址、页面标题和页面 ID。改已有页面时，先读现有标题、主要区块和发布状态，避免操作同名页面。
- 使用具备目标页面编辑权限的 WordPress 账号。只有任务需要更改站点设置时，才切到有相应权限的账号。
- 先核对插件版本与组件需求。首版用容器和八种基础组件搭建页面。客户提交表单、询盘、产品目录和模板库使用单独的实现或项目版本。[版本与兼容说明](版本与兼容说明.md)

## 编辑并保存页面

| 顺序 | 动作 | 完成依据 |
| --- | --- | --- |
| 1 | 在「页面」中新建或打开目标页，再点「使用凌凌漆编辑」。已有 ID 时可核对编辑器地址 `/wp-admin/post.php?post=<ID>&action=elementor`。 | 后台标题、ID 和画布内容与目标一致。 |
| 2 | 等待组件面板和预览画布可用，再添加或选中容器与组件。 | 面板能打开组件设置，画布显示对应元素。 |
| 3 | 一次完成一个区块。使用标题和文本组织内容，使用图片和按钮完成视觉与操作目标。 | 图片显示、按钮有有效目标、标题层级和文字符合任务。 |
| 4 | 查看桌面、平板和手机，按需调整间距、对齐和换行。 | 至少在桌面和窄屏预览中逐项核对改动。 |
| 5 | 用「保存选项 → 保存草稿」保存未发布页面。任务授权上线时，使用「发布」或已发布页面的保存动作。 | 保存完成后重载编辑器，新内容仍存在。 |
| 6 | 用预览复核草稿，或匿名访问已发布页面。点开关键链接并核对目标。 | 真实渲染、页面状态和可见修改与任务一致。 |

浏览器自动化可先按可见标签和可访问名称定位按钮，再进入预览 iframe 核对内容。`#elementor-preview-iframe` 可辅助定位画布。编辑器保存通过 `admin-ajax.php` 上的内部 `save_builder` 动作，网络结果适合排障。内容修改走编辑器保存，重载持久化才是完成依据。将内部 AJAX、REST 结构和 `_elementor_data` 用于诊断时，按当前版本源码核对。

## 示例任务

> 在测试站新建「服务介绍」草稿。做三个区块，分别展示服务标题、两段介绍和一张配图。用站内已有图片，按钮指向已确认的联系页。检查桌面和手机，保存草稿后重载并复核。交付页面 ID、草稿预览入口和检查结果。

如果任务提供素材与按钮目标，用已提供的值。出现占位内容时，在交付结果中指出具体区块。已有页面的修改范围以用户指明的区块为准。

## 维护和排障

- 若环境提供 WP-CLI，可用 `wp plugin get linglingqi-builder-open` 核对安装信息。样式缓存需要刷新时，可在确认的目标站点运行 `wp elementor flush-css`。页面搭建依照编辑器操作流程。 [命令实现](../linglingqi-builder-open/modules/wp-cli/command.php)
- 加载或保存失败时，记录站点、页面 ID、失败步骤和第一个新增的 PHP 或浏览器错误。保存动作状态不明时，先重开页面查看实际结果再决定是否重试。
- 交付时记录目标页面及 ID、草稿或已发布状态、实际修改的区块、已检查的设备宽度及预览或公开地址。将未核实的素材、链接和显示状态写在同一条交付记录中。
