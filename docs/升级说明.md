# 凌凌漆开源编辑器升级说明

从 WordPress 后台打开「插件 → 安装插件 → 上传插件」，选择目标版本的 ZIP。在已有安装上确认「使用上传的插件替换当前插件」。同一站点只启用一个 Elementor 或凌凌漆编辑器版本。

## 升级前与升级后

1. 核对当前插件版本、目标版本和安装包 SHA-256。备份 WordPress 数据库、上传目录和当前插件包。在站点副本上先做一次升级。
2. 在副本上传目标包并确认插件保持启用。打开一张既有页面，检查编辑器加载、组件、响应式样式、媒体和全局样式。另建一张测试页，保存并发布，用新会话复开，再以访客身份检查前台。
3. 如需回退，先备份现状，再装回经过验证的旧包，检查旧包是否支持升级期间写入的内容。若需恢复升级前的数据库与媒体，先保留升级后要留下的业务内容和附件。恢复旧快照会覆盖快照之后的写入。

## 1.3.0 正式版

- **适用路径**　全新安装，或用后台上传覆盖 1.1.0、1.2.0、1.3.0-rc.1、1.3.0-rc.2。升级前备份数据库、媒体和旧安装包，在副本确认结果。
- **经典版升级**　已有页面使用原来的组件。管理员如希望新页面先使用经典布局，打开「网站可视化构建器 → 编辑器模式」，选择经典优先并保存。已有 V4 或混合页仍能渲染。历史选项的规则见下方 rc.2 说明。
- **升级后检查**　打开并保存既有经典、V4 和混合页，核对匿名页面和共享样式。另建一页验原子 FAQ、原子选项卡及区块复用。
- **退回候选版**　先在副本用后台上传 rc.2 覆盖，核对现有 FAQ、Tabs 和共享样式，再决定是否应用到实际站点。
- **退回 1.1.0**　1.1.0 提供经典组件。升级后加入的 V4 元素在该版本无法完整编辑或渲染。保留运行 1.3.0 的完整副本。需要恢复原站时，先备份升级后的现状，再从同一升级前快照恢复数据库和上传目录，装回 1.1.0，确认页面、选项和媒体正常。旧快照覆盖后续写入，应先导出需要保留的内容。

## 1.3.0-rc.2 原子选项卡候选版

- **适用路径**　从 1.3.0-rc.1 用 WordPress 后台上传候选 ZIP 覆盖。兼容基线与 WordPress／PHP 声明下限沿用。
- **行为变化**　V4 面板新增「原子选项卡」。新插入预置两对原生标签与面板。可编辑公开标签文本和面板，从条目编辑器成对增删、重排。默认顺序为左右方向键同时移动焦点并激活面板。
- **已有页面**　保留原子 FAQ、经典选项卡、嵌套选项卡、原生 `e-tabs` 及其已有属性。升级时按原数据渲染，页面树与修订仍使用原格式。
- **前台引用**　标签与面板的自动 DOM ID 由渲染实例生成。若站点自订脚本或锚点曾写死旧版的自动生成 ID，请在副本核对引用。根元素自填的 CSS ID 继续由原设置控制。
- **升级后检查**　在副本打开旧文档并验证保存、复开和匿名展示。新建原子选项卡，调整标签、内容和顺序，确认键盘、移动端以及站内复制后的分组独立。
- **回退**　先备份原包、数据库和媒体。在副本验证 rc.1 可回读已有原子文档。回退后的可见入口和前台行为以 rc.1 能力为准。

## 1.3.0-rc.1 原子 FAQ 候选版

- **适用路径**　从 1.2.0 用 WordPress 后台上传 ZIP 覆盖。兼容基线与声明的 WordPress／PHP 下限保持一致。
- **行为变化**　V4 面板新增「原子 FAQ」入口。新插入时预置两项原生问答。内容面板支持直接定位问题或答案及调整条目顺序。根容器可直接保存为站内区块。
- **已有页面**　延续 `e-accordion`、各 `e-accordion-item-*` 子类型和属性键，经典手风琴保持既有元素。升级不批量写入页面或修订。同页多个 FAQ 的单项展开各自分组。结构化数据按各实例既有值解析，新建默认关闭。
- **升级后检查**　先打开、保存并匿名回读一张旧手风琴页和一张已有原子 Accordion 页。新建 FAQ，修改问题和答案，重排后保存及复开，在 375 px 和 1440 px 检查键盘和触屏行为。跨页插入两份区块，删除原稿并复查。
- **回退**　保存 1.2.0 插件包、数据库和媒体备份。在副本上检查回退后的原子 Accordion 文档及本站区块，再决定是否回退实际站点。1.2.0 的原子 Accordion 可读取已存在的原生文档，FAQ 面板入口和原子根区块的新增操作属于候选版能力。

## 1.2.0 正式版候选

- **适用路径**　可在独立 WordPress 测试站全新安装，或在站点副本从 1.1.0、1.2.0-rc.1、1.2.0-rc.2 通过后台上传替换。逐条实测状态以候选验收矩阵为准。
- **偏好与数据**　新装默认 V4 优先。已有站点保留新建页偏好及两个历史选项。缺省偏好继续按 rc.2 的规则读取历史状态。切换到经典优先后，已发布的 V4 和混合页继续使用原有文档、修订、共享类、变量及区块。
- **编辑器启动**　首次挂载可复用启动阶段已经发出的默认样式和同文档共享类读取。编辑器会等待 WordPress 登录检查初始化再主动连接 Heartbeat。
- **升级后检查**　打开并保存经典、V4 和混合页，以新会话复开，再匿名检查 375 px 和 1440 px。使用普通编辑者账号核对编辑、保存和会话续期。记录长时间遮罩的等待阶段及编辑器报错。
- **Windows 路径**　PHP 7.4 的深目录覆盖测试曾出现后台提示成功但缺少长路径文件。先在副本核对安装成员。需要验证安装完整性时，可使用较短的 WordPress 根目录重试。短目录覆盖测试逐字节核对通过。
- **回退**　保留升级前插件包、数据库和媒体备份。优先在副本验证 rc.2 可回读新建内容后再切回旧包。若只想改变默认布局，从「网站可视化构建器 → 编辑器模式」切换偏好。

## 1.2.0-rc.2 V4 安全切换候选版

- **适用路径**　可全新安装，或在副本上用后台上传替换 1.1.0、1.2.0-rc.1。各版本及运行环境的实测结果见候选验收。
- **行为变化**　从「网站可视化构建器 → 编辑器模式」选择新建页优先使用 V4 或经典。组件面板和空白画布布局按偏好提供默认入口。经典、V4 和混合页的既有组件、保存及前台渲染继续可用。
- **历史数据**　新选项尚未保存时，读取 `elementor_experiment-e_opt_in_v4` 和 `elementor_experiment-e_atomic_elements`。缺省、空值、`default` 或 `active` 随默认选择 V4；任一 `inactive`、冲突或未知持久值沿用经典优先。独立的容器实验原先关闭时，未确认偏好的站点也沿用经典优先。
- **保存偏好**　有管理员权限的用户确认表单时只写入 `linglingqi_new_page_mode`。升级和普通加载保留两个历史选项、页面树、修订、共享类、变量和区块。旧 V4 AJAX 和 REST 入口提示改用后台设置页。rc.1 因关闭原子运行时而暂时隐藏的内容，在 rc.2 可重新渲染。
- **升级后检查**　保存并复开经典、V4 和混合页面。在同一站点切换两次新建页偏好，确认两种默认入口及匿名内容。若依赖旧操作接口，改用管理员设置页确认。
- **修复**　原子内容在页面根层粘贴时分配独立元素 ID。普通编辑者保存混合页时，经典标题清理只遍历元素树，并保留页面设置。
- **回退**　想恢复经典的默认入口时，可直接切换偏好。确需降级时，先在副本验证旧包能处理当前内容。rc.1 仍可依历史选项关闭原子运行时，1.1.0 的原子支持范围更小。保留候选包、数据库和媒体备份，以便恢复原子内容。

## 1.2.0-rc.1 V4 候选版

- **适用路径**　已实测从 1.1.0 覆盖升级，也可在独立测试站全新安装。从 1.0.0 开始时，先升级到 1.1.0 并验收经典页面，再测试本候选版。
- **行为变化**　新装和未明确选择的 1.1.0 站点默认启用 V4。显式关闭、相互冲突或无法识别的历史状态保守维持关闭。现有经典内容保留原有数据结构。候选版增加原生布局、颜色与尺寸变量、共享样式、四套预设和站内区块复用。
- **升级后检查**　先保存一张经典页，再新建原子页。核对面板顺序、桌面和手机布局以及匿名渲染。若旧站曾主动关闭 V4，先确认升级后仍是经典模式。
- **模式回退**　从「网站可视化构建器 → 编辑器模式」查看提示并确认切换。关闭期间，原子内容可能暂时无法渲染或编辑。先重新启用 V4，再编辑含原子元素的页面。切换保留原子文档和区块数据。
- **版本回退**　降回 1.1.0 前，在站点副本确认已有页面不依赖 V4。需保留升级期间新增的 V4 内容时，保留可运行该内容的候选版副本与备份，再处理旧版站点。

## 1.0.0 首版

- **适用路径**　开源版首版，适用于独立 WordPress 安装。从其他 Elementor 或凌凌漆版本换入时，按站点迁移处理并先在副本验证。
- **功能范围**　容器布局和八种基础内容组件，支持响应式预览、草稿、发布和修订。
- **首次安装检查**　验证页面编辑入口、一个基础组件保存重开，以及匿名前台。迁入既有文档时，逐页检查使用的组件和全局样式，尤其是表单、模板或产品组件。
- **迁移回退**　安装前记录原站的插件版本、活动主题和数据备份。必要时在副本重新启用原插件版本，并用原站数据核对页面、样式和媒体。

## 后续每个版本的维护约定

每个稳定版、补丁版和候选版都在本页顶部增加独立条目，在提交版本更新时同步完成。条目写明适用的来源版本、行为变化、升级步骤、数据与兼容影响、升级后检查及回退方式。区分已实测的路径与建议先在副本验证的路径，并链接到该版本的安装包、校验值和验收记录。沿用的通用步骤可引用本页，版本特有的注意事项写在该版本条目中。
