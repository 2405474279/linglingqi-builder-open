### 模式安全切换

新建页偏好控制面板排序、同名搜索结果和空白画布布局入口。无论偏好如何，V4 兼容标记、原子注册、样式解析和既有文档保存都持续可用。后台表单只保存 `linglingqi_new_page_mode`。冷启动和覆盖升级仅读取旧值，保留历史记录。旧 AJAX 和 REST 请求返回后台设置入口。原子运行时持续可用，页面树、修订、变量、共享类和区块保留原有结构。[历史选项和升级说明](升级说明.md)

根层原子粘贴采用 Elementor 4.4.0 的定向修复思路。注册待挂载元素前生成整棵副本的新 ID，现有原生钩子继续重映射局部样式，复制内容继续引用原有共享类和变量。[核对来源与范围](upstream-provenance.md)

预检时，普通编辑者从真实编辑器保存包含经典标题和原子元素的混合页会产生 PHP 警告。旧清理逻辑遍历了整份保存请求，也假定布局节点具有 `widgetType`。候选包把清理范围限定为元素树，仅在经典标题有文本值时清理，保留页面设置及原子数据。

### 加载等待及边界

- PHP 7.4 组合的三个编辑页面实测约 47.5、52.4、39.7 秒进入可编辑状态，均加载了 `editor.min.js` 并自行关闭遮罩。
- 较新组合并行验收时，有一次普通编辑者的冷加载耗时约 223.6 秒。iframe 的 DOM 在发起导航后约 113.8 秒完成，其载入事件在约 131.9 秒结束，后续文档全局类请求约 222.7 秒返回，遮罩随后关闭。慢段落在 iframe 载入后的挂载与 AJAX／REST，相关请求未出现 5xx。普通编辑者访问仅限管理者的类用量接口得到预期的 403。
- 同一最终包、同一个混合页、同一角色使用新浏览器上下文串行复开，约 17.6 秒取得原生视图，最后一批文档类请求约 23.8 秒完成，约 24.8 秒关闭遮罩。确认实际加载 `common.min.js`、`editor.min.js`、`editor-canvas.min.js` 和 `editor-elements.min.js`。后台偏好套件的八次打开耗时 26.3–30.6 秒。串行复验未复现长时间遮罩，现有数据表明并行负载与等待相关，尚不足以归因到单一接口或确认版本间的性能差异。
- 预检及最终 PHP 日志中的 WordPress.org 连接警告来自隔离站的外部联网限制。某些较新后台导航偶见 Chromium 的 ViewTransition 取消信息。记录这些环境现象与混合页保存时实际修复的插件警告分开。
- WordPress 6.8 普通编辑者会话中，核心 `wp-auth-check.min.js?ver=6.8:2:655` 两次报告读取未定义对象的 `hasClass`。实测仍可复开并保存，匿名回读通过。该通知的触发条件尚未专项定位。
- 此次根层粘贴修复作用于新的粘贴操作。模式切换和升级不批量改写已有文档。

### 1.1.0 基线实测

- 新装后两项 V4 选项缺失，容器已启用，`e_opt_in_v4` 和 `e_atomic_elements` 均未启用，原子组件注册数为零。旧 opt-in 方法即使写入 `active`，下一请求仍无法启用原子功能。旧版编辑器可打开和渲染经典标题。
- 原因是模块清单未初始化 V4 opt-in，而原子模块的不可变实验默认是关闭。资源包在磁盘上存在，编辑器没有加载相关包。与官方 4.3.6 相比，缺少原子表单、部分整站导入导出和类用量管理等资源。[上游差异与许可](upstream-provenance.md)

### 已知范围

- 原子图库、折叠 FAQ、Tabs、参数表及独立原子图标的交互验收留在下一批。示范图片墙是原子组合。工业产品、询盘、授权、计费属于扩展范围。
- SQLite 仅用于本地验收。包头的最低 PHP、WordPress 版本以及其他主题、数据库组合未全量覆盖。此次 WordPress 后台页面偶见 Chromium 的 ViewTransition 取消信息。Windows 单进程 PHP 测试服务器在多套用例并行时曾超过 90 秒等待阈值，串行跟踪确认原生预览挂载完成，约 37.5 秒后关闭加载遮罩，完整用例复验通过。
- 区块库面向站内复用。同站共享依赖继续共用；跨站样本需要解析目标站类、变量和媒体。上游 4.4.x 的变更未并入此包。切换关闭时，已有原子内容可能暂时不显示，按后台提示重新启用后再编辑。
